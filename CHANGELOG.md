# Changelog

Format based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/).

## [Unreleased]

### Added

- Management-API token authentication: when `api.auth_token` (or the `NIPS_API_TOKEN` env var) is set, every `/api/v1/*` route requires the `X-API-Token` header; an empty token disables auth with a startup warning. Wildcard CORS was removed in favor of an explicit origin allowlist.
- BLOCK-verdict escalation policy (`engine/block_policy.py`): strikes per source IP inside a rolling window escalate to a temp ban (kernel DROP + in-memory blacklist entry with a TTL, auto-lifted by an expiry sweeper) and, after repeated temp bans, to a permanent ban persisted to `rules.json`. A single anomaly no longer installs a permanent kernel DROP.
- `GET /api/v1/blocks` endpoint exposing the live escalation state, plus `kernel_blocked_ips` and `detection_loop_stale_seconds` fields on `/api/v1/status`.
- `broken_detectors` (circuit-breaker state) exposed on `/api/v1/status`, as documented in SECURITY.md.
- Parquet support in `DatasetLoader`: `.parquet` files are read as Parquet; CSV remains the default.
- Detector contract: `BaseDetector` gains `configure()`, `ready` and `status()`, and mounting is driven by config (`engine.ml.enabled`, `engine.ml.detectors`) instead of hardcoded wiring in the entrypoints. `networksecurity/engine/threshold_detector.py` is a complete worked example; with the switch off, no ML module is imported at all, so deleting `engine/kitsune/` and `engine/lucid/` yields a supported rules-only deployment.
- `scripts/verify_detector_contract.py`: contract, switch, external mount, skipped-on-failure, and config-degradation checks.
- Per-kind event-store write counters (`written_alerts` / `written_audit`) in `stats()`; the store-wide `written` total keeps its meaning, so `nips_alert_events_written_total` is unchanged.
- `requirements-dev.txt` separating development/CI dependencies (Parquet engine, scapy) from the runtime install.
- Shadow mode for ML detectors: a detector entry with `enforce: false` is consulted and its verdicts recorded — BLOCKs count into `total_shadow_blocked` on `/api/v1/status` and `nips_packets_shadow_blocked_total` on `/metrics`, and every shadow verdict reaches the alert trail as an `action=log` row prefixed `[shadow]` — but no packet is dropped, no strike is recorded and no chain exit is short-circuited. A healthy shadow detector counts as ML coverage for the fail-closed posture.
- `preflight` gate that imports every production module in an environment built from `requirements.txt` alone — the class of gap where a dependency exists only in the CI install list.
- Real-data evaluation scripts: UNSW-NB15 pcap reconstruction (`scripts/build_unsw_pcap.py`) and end-to-end per-category evaluation (`scripts/evaluate_pcap.py`); cross-module regression scripts (`scripts/verify_*.py`) including a post-training FPR regression assertion in CI (`scripts/verify_fpr_regression.py`).
- Large-scale attack simulation script (`scripts/attack_simulation.py`) for benchmarking detection efficacy across attack categories.
- Comprehensive CI pipeline: lint, security scan, unit tests, FPR regression guard, PR title lint, and branch name checks.

### Changed

- Learning detection is off by default (`engine.ml.enabled: false`). The distinction is now explicit: switching it off is a decision, so packets the rule engine does not decide are allowed; having it on and unable to run is an outage, so those packets are dropped as before.
- Removed `DetectionPipeline(short_circuit_on_block=...)`: a constructor flag no caller passed and no config key reached, whose "strongest-confidence BLOCK wins" semantics are unsound across detectors (an RMSE ratio and a probability are not comparable). Shadow mode (`enforce: false`) is the supported way to let detectors observe without deciding.
- A detector mounted without its model (`ready: false`) is no longer registered and no longer counts as ML coverage. It used to answer `LOG`, which both ended the chain and made the pipeline believe detection had run — enough for a tripped live detector behind it to disable fail-closed silently.
- `/api/v1/status` passes `pipeline.status()` through instead of copying fields one by one, and splits detector state into `ml_enabled` / `ml_consulted` / `ml_idle` plus a per-detector `detector_status` (a detector's own `status()` output, contained if it raises), so "not deployed", "could not run", "warming up" and "running" are no longer the same sentence.
- README's `## Benchmarks` became `## Measured results and limits`: every number now carries the command that reproduces it.
- Real-capture evaluation now trains at the shipped grace periods (5 000 + 50 000, `config/config.yaml`) instead of a shortened 2 000 + 30 000 that fit training and a detection window into one capture. The override also fitted KitNET's feature map on 2 000 packets — whatever arrived first — which made the measured operating point a property of the packet draw: redrawing the same 1 680 flows moved it from 1.3% to 52% of packets blocked with no code change, and at 2 000 packets the fitting window covers 43 flows with one of them supplying a third of it. At the shipped values both draws stay out of that regime; the READMEs quote the measured range.
- The real-capture quality gate scores three fixed draws (the low, middle and high of a twelve-seed sweep) and bounds their median false-positive rate instead of bounding a single unseeded run, plus a wider bound that no draw is catastrophic. KitNET draws its autoencoder weights from the global RNG, which on this capture spreads the false-positive rate from 2.1% to 10.5% across seeds — the old single-run 5% bound sat inside that spread and would fail roughly one run in five with nothing changed. Fixed seeds make the gate reproducible (`--seed` in `evaluate_pcap.py` pins a draw bit-for-bit, verified by rerunning one). It also fails when no draw flags a single attack packet, the dead-detector case its docstring described but never checked.
- The truth-chain checks on the bundled capture moved from the nightly gate into the PR layer. They were inheriting `real_capture_quality`'s schedule: `ci.yml`'s `triage` excludes that *name* from the unit matrix because of what the measurement costs — it trains KitNET at the shipped grace periods and scores three draws — so the cheap half rode along with the expensive half, and a regression in the truth chain (the builder folding the label back into the headers, the evaluator inferring truth from an address) stayed green on every pull request until the next night. The checks now live in `scripts/capture_truth.py`; the new `scripts/verify_capture_truth.py` runs them in the unit matrix, auto-enumerated like every other suite so there is no list to hand-edit; and `verify_real_capture_quality.py` imports the same definition rather than keeping a copy. The whole suite is ~90s (54s of it a byte-identical capture rebuild), against that job's 20-minute timeout.
- The address-independence check now reads its addresses back out of the pcap instead of out of the sidecar it is checking. Running the statistics on `record["client"]` was the sidecar agreeing with itself; it says nothing about the wire. Reading them from the capture also produced a free integrity check — the labelled flow set, each flow's endpoints and each flow's packet count must match the capture — and the read is deliberately independent of `PcapLoader`, so a frame the pipeline's parser skips shows up as a packet-count disagreement.
- CI restructured into three blocking layers (static / unit / system) behind one aggregate `ci/required` check, so branch protection pins a single name and skipped jobs no longer block documentation-only PRs; the eight module suites moved from serial steps in one job to a parallel matrix. Slow calibration-only checks (real-capture detection quality, LUCID training, attack simulation), the Python 3.13 sweep and the full static reports moved to `.github/workflows/nightly.yml`.
- `EventStore.flush()` waits for the in-flight batch to commit, not just for the queue to drain, so `stats()` read straight after a flush cannot report a total that has not caught up.
- `DatasetLoader` reports a missing Parquet engine as an actionable `ImportError` instead of surfacing pandas' internal one.
- TensorFlow moved to the `nips[lucid]` extra: default installs no longer pull in 500 MB+ of dependencies; the LUCID adapter stays inactive without it (lazy import).
- Config loading reworked: `config.yaml` now drives the `api` block (host/port, auth token, CORS), the `engine` block, and the `blocking` (escalation) policy; paths are package-root anchored so the CWD no longer matters, and fallback defaults include `::1` in `safe_ips`.
- Detection enforcement is fail-closed: detection errors and timeouts drop only the in-flight packet and never commit a permanent block.
- Applied ruff auto-fix across the entire project and updated CONTRIBUTING.md.
- Updated README to match the current codebase (CLI commands, API endpoints, architecture tree).
- Documentation audit against the code: CODE_STYLE.md now lists all six packages (including `observability/`, with its dependency rules) and replaces a model-inference example that taught the removed LOG-answer anti-pattern; CONTRIBUTING.md's commit-message examples match the repository's actual Chinese conventional style, `dev` joins the branch-name exemptions, and the stale CI description in the review process now points at the layer table; both READMEs merge the duplicated Configure/Configuration sections, complete the Layout trees (`signature_engine.py`, `utils/reload.py`, `live_nfqueue_topology.sh`, `capture_labels.py`, `capture_truth.py`), and correct the hot-reload list (`allowed_icmp_types` does re-apply) and the `cors_origins` excerpt.

### Removed

- Web status page: the `/` dashboard route, `templates/` (`index.html`), and the static-file mount are gone — the management surface is now the REST API + CLI only. `jinja2` and `python-multipart` were dropped from the dependencies.

### Fixed

- `verify_engine_module.py` RL7 — the check that every engine knob is either applied live or declared restart-required — derived its expected set from `load_engine_config()`/`load_ml_config()`, which return a fixed dict of the keys those loaders already know. A knob newly written into `config/config.yaml` that no loader maps was therefore invisible to the one check whose job is to notice exactly that, which is how `max_autoencoder_size` went unmentioned for a whole release cycle. It now reads the raw YAML, and **RL7b** proves the check can still see: it feeds the same logic a copy of the config carrying a key no loader has ever heard of and requires that key back. Reverting to the normalised view turns RL7b red (`caught=[]`).
- Pipeline: a `ready` that raises now costs a detector **one** breaker failure per packet, not two or three. #23 routed the read through a helper that counted the failure itself, but the same packet is read again on the way out — the fail-closed `expected` line counted a second time and the detector's own exception a third — so `FAILURE_THRESHOLD: 5` meant three packets in practice, and a `GET /api/v1/status` was moving breaker state. `_ready_state()` now answers *(supposed to cover, did the read fail)* without counting; the counting lives once per packet in the loop, and the fail-closed decision and `status()` only look. P11a pins the per-packet count sequence, and the mutant that restores the unconditional second count goes red on it (`counts/packet=[2, 4, 6, 6, 6, 6, 6, 6]`).
- Evaluator (`--buckets`): the drift profile now reconciles against the run's own scored-packet count instead of against the list it was handed, and the run fails (exit 3) when they disagree. The shape of that series is the evidence a calibration decision gets made on, so a collection step that quietly kept only part of the window — the blocked packets, say — had to be impossible to miss. Previously every gate checked the printer's internal arithmetic and nothing checked what the printer was fed: a mutant filtering `samples.append` to blocked-only kept the nightly's seven gated fields exactly as parseable and printed a self-consistent profile of a different run, while `verify_capture_truth.py` stayed green. The header now carries `(29/140 scored packets accounted for)`; `capture_truth` parses those two numbers out of a real run at **two** operating points — the probe's default threshold flags every packet, where a blocked-only series would reconcile by coincidence, and a 40-packet calibration window at p100 flags 29 of 140, where it cannot — and it fails if the two runs turn out indistinguishable. Reproduced against that mutant: exit 3 plus two named failures.
- Nightly (`.github/workflows/nightly.yml`): the two LUCID steps were still written for the pre-assembly wiring and broke when mounting moved behind `engine.ml.detectors`. "App registers the detector from the saved model" flipped `engine.ml.enabled` and pointed `model_path` at the trained file — but the shipped config keeps `- uses: lucid` commented out, so `attach_detectors` never built one and `assert "LucidDetectorAdapter" in names` could only fail. It is green on `main` today only because `main`'s `app.py` still mounts LUCID directly from `model_path`, the wiring this branch removed: merging dev into `main` would have turned that job red the first night, and its follow-up step ("an unloadable model leaves the detector out of the pipeline") was a not-in assertion against an entry that was never listed — a check that cannot fail. The step now injects the `lucid` entry too and asserts the *parsed* `engine.ml.detectors` contains it before importing the app; the broken-model step carries the same positive control, so its not-in means "the loader refused a bad model". `verify_detector_contract.py` C21 keeps the assumption visible in the PR layer: a built-in named in the list must reach its builder — mount, or log the reason — because silence is exactly what made the nightly step decorative. Reproduced both directions: replaying the old rewrite against the shipped config yields `detectors=['kitsune']`, the new one `['kitsune', 'lucid']`; dropping `lucid` from the builder table turns C21 red (22/22 → 21/22).
- Evaluator: a sidecar that labels only one class is refused, not scored. The empty-label guard covered the case where *nothing* matched, but a sidecar matching five attack packets and no normal ones still printed `detection rate (TPR) 100.0%` and `false positive rate 0.0%` with exit code 0 — one of the two rates had no denominator and the page looked like a clean run. Both rates now require both classes inside the scoring window, the refusal names the class that is missing, and the summary reports coverage (`179 packets scored, 5 labelled`) instead of calling the labelled subset the "evaluation window". `verify_real_capture_quality.py` has long treated a window with no attack or no normal packets as a failure for the bundled capture; this moves that invariant into the program that prints the numbers, so it also holds for any `--labels` an operator brings. Pinned by `capture_truth`'s new attack-only probe, which selects its flows from the packets the probe actually scores — a probe whose labels never reach the window silently degenerates into the empty-set case, and the first version of this probe did exactly that: it stayed green against a mutant that reintroduced the bug, and only the discriminating version turns red.
- Reload: `engine.ml.enabled`, `engine.ml.detectors` and `engine.kitsune.max_autoencoder_size` are now declared restart-required in the reload summary. The list was hand-copied and had drifted: an operator editing the ML switch and calling `POST /api/v1/rules/reload` got `errors: []` and a 200 while the detection posture stayed exactly as it was, because `_apply_engine_knobs` only touches the rule engine and nothing named the rest. `verify_engine_module.py` RL7 derives the expected keys from the config schema (`load_engine_config()["kitsune"]`, `load_ml_config()`) rather than typing the list twice, so a knob that is neither applied live nor declared restart-required fails the suite — which is the class of gap that let these three sit unmentioned. The hot-reload section of both READMEs now lists them.
- Example detector (`networksecurity/engine/threshold_detector.py`): `configure()` decided whether to store an int or a float with `default == int(default)` — which is also true of the float default `5.0`, so `window_seconds` always took the integer branch. `0.5` cleared its own floor check and was then stored as `0`: a detector counting packets inside a zero-length window, never tripping, and still counted as ML coverage; `2.5` silently became `2`. Classification now follows the default's *type*, the floor is re-checked after narrowing, `bool` params are refused (`bool` is an `int` subclass, so `max_packets: true` used to store `1`), and a non-numeric value raises the same `ValueError` as every other refusal. `verify_detector_contract.py` C14b feeds real packets through a sub-second window — it fails on behaviour, not on the stored attribute — and C14c pins integer narrowing plus the bool refusal; restoring the old comparison turns both red (21/23, 2 CONFIRMED-BUG). This is the detector the docs hold up as the copyable contract example, so its defects were third-party defects.
- Pipeline: `ml_unavailable` is the machine-readable "fail-closed is dropping undecided traffic right now", and `/metrics` republishes it as `nips_ml_unavailable` — but it compared the tripped-detector count against every *registered* detector. With one detector tripped and a second mounted without its model, nothing can score and every undecided packet is dropped, yet the field reported `False` and the gauge stayed at 0 through a full outage. It is now computed over the same expected set the fail-closed decision uses (mounted and able to score), and `ml_consulted` is derived from that set instead of reading `ready` a second time. `verify_engine_module.py` P12a pins the mixed outage and P12b pins the other direction — a model-less detector alone is rules-only operation, not an outage; restoring the registered-count comparison turns P12a red.
- Pipeline: a detector's `ready` is contract code, and a property is allowed to raise — but `ready` was read bare in three places, so that exception escaped `process_packet()` without ever reaching the circuit breaker. The interceptor's catch-all then dropped every packet with an unthrottled `logger.exception`, `broken_detectors` stayed empty, and `detection_unavailable_drops` never moved: the failure mode `FAILURE_THRESHOLD` exists to prevent, entered through the extension point this branch series added. `ready` is now read through one helper that counts the failure (so the breaker still trips and the outage still reports itself) and answers *supposed to cover* — answering False would take a detector out of the fail-closed set precisely when we cannot tell whether it can score. `status()` reads it without touching breaker state, so a raising `ready` can no longer take `/api/v1/status` down. `verify_engine_module.py` P11a–P11c pin all three behaviours; reverting any one read to bare `getattr` turns P11a red.
- Kitsune: the anomaly threshold was the percentile of RMSEs taken *during* the AD grace — while the output layer's normalisation was still being updated — and was then applied to scores taken after it froze. On a real capture that mismatch put the operating point inside the normal traffic's own distribution: 89% of ordinary packets were flagged in the first bucket after training, and no percentile short of 99.99 undid it. The threshold is now calibrated on the first 10% of packets scored *after* the freeze (abstained, untrained, unflagged — a third warm-up window, not a blind spot in the gate), which flags 0 of 47,115 post-warm-up packets on the same capture and 1.00% of a stationary stream at p99. On the bundled reconstruction the same change moves the twelve-seed spread from 2.1–10.5% false positives / 0.9–2.9% detection to 0.4–1.4% / 0.3–0.8% (median 0.9%), with one draw in twelve — `--seed 2` — still at 20.9% / 13.6%: per-initialisation instability is narrowed, not cured. `verify_engine_module.py` K10/K11 pin the mechanism and that a real shift is still caught; `evaluate_pcap.py --calibration-packets 0` restores the old source for comparison. `threshold_source` now reads `pending` until a threshold actually exists (it used to answer `calibration` from the first second of warm-up when calibration was disabled), and the warm-up log counts the calibration window in the packets-before-detection figure it prints. K12 pins both readings of that field.
- `scripts/verify_fpr_regression.py`: its attack-detection half printed "TPR on SYN flood 100%" while drawing 500 packets from a 5 148-address pool at 1 ms spacing — about one packet per source, so the per-source limit was never approached — and scoring them through the whole pipeline with ML enabled. That 100% was the anomaly detector flagging everything, which is the exact failure this file exists to catch, and the rule engine it was credited to was built on `max_connections=1000` rather than the shipped 100. It now sends a real single-source flood through a rules-only pipeline at shipped values (**80.0%** of 500 blocked; the first 100 fit the budget) and reports what the same 2 000 normal packets cost with and without the detector in the path (0 vs 36). Both halves were checked against mutants: spreading the flood over 500 sources drops detection to 0% and fails the gate, and forcing the threshold to −1 puts false positives at 100% and fails it. The README rows that quoted the old numbers are corrected with the new ones.
- Kitsune: removed AfterImage wall-clock features that caused 100% false positives on long-running sessions; fixed KitNET output-layer normalization ordering; wired `threshold_percentile`; `is_ready` exposed as a property.
- Rule engine: O(n) full-table scan replaced with O(1) LRU eviction in the rate limiter; counters and status snapshots taken under lock; rate-limit cap raised and eviction clarified.
- Interception: loopback self-banning prevented, ban state kept in sync across layers, NFQUEUE queue numbers aligned, shutdown/close races and cross-thread data races fixed, fail-open hole closed; `Interceptor.unblock_ip` and the unblock endpoint now also clear kernel-level bans.
- Data: PcapLoader IP-parsing scope fix (real pcaps no longer parse every IP to None); pcap loader rewritten to mirror the live parser and support more link layers; scapy import deferred to call time; Infinity values no longer leak through Parquet datasets.
- API/app: rule-entry IP/CIDR validation, atomic `rules.json` writes, absolute rules path, alerts list lock, engine config wired into the API/CLI start path, undefined `RULES_FILE_DEFAULT` reference.
- Added missing `Verdict` import and suppressed bandit false positives in CI.
- `scripts/attack_simulation.py`: the mixed-traffic phase kept its own tallies, so the summary table — and the headline false-positive rate — silently excluded all of its packets. On an interleaved run that dropped 60,000 verdicts including a measured ~100% false-positive rate on normal traffic, which the report then printed as a fraction of a percent. Phase 3 now feeds the same counters as every other phase, and the report prints a reconciliation warning whenever the summary stops matching the pipeline's own block count.
- The bundled "real capture" benchmark no longer writes its answer key into the capture. `build_unsw_pcap.py` drew attack flows' source addresses from one block and normal traffic's from another, and `evaluate_pcap.py` recovered the label by reading that block back out of the header, so a detector keyed on the source address scored 100% for free and the reported detection rate measured the reconstruction. Addresses are now drawn independently of the label, labels live in a sidecar (`scripts/capture_labels.py`) that the evaluator takes as an explicit input, and a capture without one is refused rather than scored (`--no-labels` reports verdicts and block reasons only). `scripts/capture_truth.py` holds the checks that keep the leak from coming back: the source address must not predict the label (permutation test, self-tested on a deliberately leaky partition — a check that cannot fail is not a check), the retired `175.45.176.*`-means-attack rule must not separate the classes, the sidecar must describe the capture it will be scored against (every labelled flow present on the wire, same endpoints, same packet count), and three evaluator runs must refuse to invent truth.
- The evaluator now refuses a sidecar that describes none of the capture. Every packet unmatched means the labelled set is empty, and an empty set scores 0.0% false positives and 0.0% detection — the numbers a perfect detector produces, indistinguishable in a report from success. It used to print those; the gate caught it only because it checked `unmatched` separately. A `--limit` inside the grace periods ends the same way, with a message naming both causes.
- Fixed a check that could not fail on the developer's machine: the truth checks reused any capture already on disk, so editing the builder and re-running verified the *previous* build. The capture is now rebuilt when it is older than the builder or than the dataset it is built from (in CI neither file exists, so it is a straight build either way).
- Style and security findings that cannot fail the build are now reported as such instead of running behind an `--exit-zero` that made them look like passing gates.

### Performance

- RateLimiter over-limit throughput 736k → 953k checks/s (O(1) LRU eviction); FlowTracker high-entropy flood throughput 412 → 257,799 pkt/s (LRU + heap expiry sweep) with bounded memory.

## [1.0.0] — 2026-07-30

### Rewrite

Complete project restructure from phishing URL classification demo to a real Network Intrusion Prevention System.

- Four-layer architecture: interception → features → engine → management
- NFQUEUE + iptables real-time traffic interception (Linux)
- AfterImage 100-dim incremental statistics + KitNET anomaly detection (Kitsune, NDSS'18)
- LUCID CNN-based DDoS flow detection (IEEE TNSM 2020)
- Rule engine: IP blacklist/whitelist, protocol filter, rate limiting
- DetectionPipeline with short-circuit semantics
- REST API + CLI + lightweight status page
- CI: keyword scan for simulation code, import check, smoke test

### Removed

All old simulation/demo code:
- Protection service (memory-only state machine with no OS blocking)
- Firewall module (in-memory classifier, no iptables integration)
- URL feature extractor (phishing detection, 30 fixed features)
- Traffic simulator (synthetic HTTP log generator)
- Demo algorithms script (random data generators)
- Benchmarks directory (attack simulation scripts)
- RL/DL/ML engine dead code (not wired to NIPS pipeline)
- Old stats module, training pipeline, data ingestion components
- Old templates (predict, protection, dashboard, training, model select)
